## 2. 实施范围

在 Vela 原生入口内实现日志，每批次一个文件。记录项目、视频、任务序号、开始、目标、过程、最终输出指标与批次统计；保留原有批次失败继续语义。Jasna 实施不在本次范围内。

## 3. 执行记录

- Codex：将已获 Mengsk 批准的 T9 设计记录归档，建立 T10 实施记录；开始并行处理可信元数据、单文件日志核心与子进程日志接入。
- Codex：原生单视频与批量入口自动生成独立运行目录，每批次仅一份 `vela.log`，同步控制台；逐视频记录输入、配置目标、实际编码器参数、过程、输出摘要以及终态。相对目录与序号区分同名视频。
- Codex：视频流与容器码率分开记录，缺失字段不使用算法默认值冒充；最终摘要读取已封装文件的分辨率、帧率、码率和大小。探测不可用时明确注明，未生成完整文件时不报告成功。
- Codex：Python 与原生 stdout／stderr、多 worker 输出及 FFmpeg 错误集中进入同一日志；日志队列在当前视频收尾时排空，随后才进入下一视频。真实控制台描述符副本避免日志回流。
- Codex：实际编码参数在 worker 选择编码器后记录，包含质量控制回退下未设置码率的情况；复用分段注明本轮新处理帧数为 0，未运行编码器。进度采用实际计时，移除原有估造的初始速度。
- Codex：逐任务终态独立于批次退出码，保留批次失败后继续且最终可返回 0 的行为；缺失分段、异常进程和封装失败不会误报完成。覆盖队列扫描中断、当前任务中断及终态附近信号，避免重复计数。
- Codex：独立代码审阅指出终态附近的信号计数窗口，已改为每任务一个终态映射并补充回归；日志排空、子进程与描述符清理经复核。
