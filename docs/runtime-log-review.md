## 2. 执行方式

Jasna 和 Vela 是两个独立项目，分别使用各自已有的启动命令。运行记录以各自实际日志为准，不新增 benchmark 入口、随机权重替代流程或测试框架。

Mengsk 执行项目命令并审阅结果。助手负责组织本次运行新产生的日志、记录参数和执行状态；本说明不要求查看输入画面或输出画面。

每次运行保留实际命令、参数、开始与结束时间、进程退出码以及 stdout/stderr。文件名、机器连接和部署路径保留在 Git 忽略的私有记录中；公开报告只记录匿名任务编号与技术参数。

## 3. 日志组织

日志放在 `.tmp/restoration-order/private/runtime-logs/<collection-id>/`，由索引说明本次覆盖范围。

- `jasna.stdout.log`、`jasna.stderr.log`：Jasna 的两个原始输出流。
- `vela.stdout.log`、`vela.stderr.log`：Vela 的两个原始输出流；未获取时明确缺失，不创建假成功日志。
- `<project>.state.json`：采集时的运行状态与可确认的退出码。
- `<project>.review.log`：可选的查看版，只去除 ANSI 和压缩连续进度条；原始日志始终保留。
- `collection.json`：采集范围、时间和完整性说明。
- `README.md`：直接指向日志的人工查看索引。

日志从新一次原生任务开始时记录。容器不存在或已删除，不以找回旧容器日志作为前置条件；源码项目与容器生命周期分别管理。

对于本次运行中的容器，可以使用 `docker logs --timestamps` 读取日志，通过 `docker inspect` 查询状态。限定尾部行数时记录截断范围；历史采集只作留档，不纳入当前对照。

## 4. 记录与审阅

优先从原生日志记录模型与后端、设备规格、分辨率、帧数、耗时、错误和完成标志。日志没有提供的字段写“未记录”，不以估计或组件测试数字填补。

两个项目的日志分别归档。只有确认对应同一次输入、参数和实际运行顺序，才能作为一组对照；历史日志、容器退出码和逐文件成功状态分开记录。

助手不代签 Mengsk 的结果审阅，也不把日志整理完成写成视频处理或画质验收完成。
