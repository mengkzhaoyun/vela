## 2. 执行方式

Jasna 和 Vela 是两个独立项目，分别使用各自已有的启动命令。运行记录以各自实际日志为准，不新增 benchmark 入口、随机权重替代流程或测试框架。

Mengsk 执行项目命令并审阅结果。每个项目每次运行只保留一个日志文件，stdout 与 stderr 合并写入，按时间记录“开始处理、处理过程、处理结果”。

## 3. 输出位置

日志放在 `.tmp/restoration-order/private/runtime-logs/<run-id>/`：

- `jasna.log`：一次 Jasna 运行的完整日志。
- `vela.log`：一次 Vela 运行的完整日志。

一次只运行其中一个项目，就只生成对应的一份日志。重跑使用新的运行编号，不覆盖上次记录；不另建状态 JSON、查看版或索引文件。

日志从新任务开始时记录，历史采集只留档，不纳入本次对照。日志目录受 Git 忽略；公开文档不复制真实片名、连接信息或私有部署路径。

## 4. 输出内容

### 4.1 开始处理

记录开始时间、项目名称、输入文件、输出位置、模型及本次实际启动参数。凭据不写入日志。

### 4.2 处理过程

持续记录程序原生输出，包括当前阶段、已处理帧数或进度、速度、告警、错误及异常堆栈。程序提供哪些信息就记录哪些，不另跑 benchmark 补字段，不对画面作评价。

### 4.3 处理结果

结束时记录完成时间、成功／失败／中断状态、进程退出码、总耗时和实际输出位置；程序提供输出帧数、分辨率或大小时一并保留。失败时保留错误原因，不只写一个退出码。

成功状态依据进程退出码及程序完成记录确认；没有结束记录的日志不能自动视为成功。日志未提供的字段写“未记录”。Mengsk 直接查看这一份日志审阅执行情况。

## 5. 预期输出样例

每行使用 `YYYY-MM-DD HH:mm:ss [类别] 正文`，开始行注明时区。stdout 和 stderr 写入同一文件，不再区分两份日志。动态进度条按换行记录；普通进度沿用程序的输出频率，不另建采样任务。阶段切换、告警、错误和结束记录完整保留。

### 5.5 中断与日志突然结束

已经获取到中断信号和进程状态时，在同一个文件追加结果。例如收到 Ctrl+C 且实际返回码为 130：

```text
2026-10-28 10:15:20 [处理结果] 状态=中断 退出码=130 总耗时=20.0秒
2026-10-28 10:15:20 [处理结果] 原因=收到中断信号 输出=未确认完成
```

退出码以实际获取的值为准。若机器断电、日志记录进程也被终止，可能根本没有结果尾行；此时只能标为“缺少结束记录，结果未知”，不能补造成功、耗时或退出码。
